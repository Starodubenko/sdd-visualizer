## Do

- В `api.ts` вернуть вызовы: `POST /api/features` `{ project, featureId }`, `DELETE /api/features?path=`, `POST /api/document/status` `{ path, status }`, `POST /api/publish` `{ project }`, `PUT /api/projects/:name` `{ remote, token }`. Не возвращать сохранение тела документа и загрузку скриншота.
- В шапке справа, рядом с переключателем темы, меню «Действия»: «Добавить фичу», «Удалить фичу», «Опубликовать». Меню закрывается снаружи через `useCloseOnOutside`.
- «Добавить фичу» открывает модалку с полем имени (kebab-case) и кнопкой «Создать». После успеха обновить дерево проекта и открыть `docs/<проект>/<фича>`.
- «Удалить фичу» подтверждает «Удалить фичу?». Путь фичи берётся из выбранного каталога или из пути открытого файла: отрезать имя файла и каталог `in-progress`, `ready-to-implement` или `done`. Если фича не выбрана, показать ошибку и не вызывать API. После успеха обновить дерево и выбрать проект.
- «Опубликовать» подтверждает «Опубликовать проект <имя>?» и публикует выбранный в шапке проект.
- В полосе документа у ключевого файла (`analyst.md`, `designer.md`, `backend.md`, `tester.yaml`, `frontend.md`) меню «Действия» предлагает два других статуса. Подтверждение: «Перенести файл в «<подпись>»?». Подписи уже есть в `statusLabel`. После ответа сервера открыть новый путь и обновить дерево проекта и фичи. У остальных файлов этого меню нет.
- Админка: поле адреса, поле токена (пустое, без подстановки сохранённого токена) и «Сохранить». Сохранение подтверждается «Сохранить настройки проекта?». Пустой токен уходит как пустая строка, чтобы сервер сохранил прежний. Имя каталога остаётся текстом.
- Ошибки API показывать текстом ответа.

## Do not

- Не вызывать `PUT /api/document`.
- Не возвращать «Исходный текст», редактор и `TaskForm`.
- Не менять сервер, метод и фикстуры.

## Done when

- В `apps/web/src` нет `saveDocument` и нет `PUT` документа.
- Меню создания, удаления, публикации и смены статуса есть, запрос уходит только после подтверждения.
- `npm test -w @sdd/web` проходит.
