## Read

- `.cursor/plans/docs-settings/SPEC.md`
- `.cursor/plans/docs-settings/state.md`
- `docs/method/05-docs-repo.md` — раздел «Директория фичи»
- `apps/server/src/documents/templates/render-templates.ts` — текущие тексты пяти шаблонов

## Do

- В `docs/method/05-docs-repo.md` после схемы директории фичи добавить короткий раздел «Настройки типов документов»: каталог `docs/settings` не проект и не показывается в дереве фич; в каждом каталоге типа лежат `template.*` и `agent.md`; в корне `orchestrator.md`; новая фича кладёт в `in-progress` файл на каждый тип, имя — каталог плюс расширение шаблона, `{{feature}}` становится feature-id.
- Создать `docs/settings/` как в SPEC. Текст каждого `template.*` взять из соответствующей функции `render-templates.ts`. Вместо подставленного feature-id писать `{{feature}}` в заголовке и в строке `feature:`. Остальной текст шаблона не переписывать.
- `agent.md` каждого типа: этот агент пишет только файл своего типа в каталоге фичи; форма документа — соседний шаблон; разделы не добавлять и не удалять; критерии приёмки из шаблона сохранять.
- `orchestrator.md`: по имени открытого файла фичи (`analyst.md`, `designer.md`, `backend.md`, `tester.yaml`, `frontend.md`) выбрать каталог `docs/settings/<тип>/` и следовать его `agent.md` и соседнему шаблону. Для неизвестного имени файл не выдумывать.
- Скопировать получившееся дерево в `apps/server/test/fixtures/docs/settings/` без отличий.

## Do not

- Не менять `apps/server/src` и `apps/web`.
- Не менять уже существующие документы фич billing и payments.
- Не добавлять шестой тип документа.

## Done when

- `docs/settings` и `apps/server/test/fixtures/docs/settings` совпадают по содержимому.
- В шаблонах есть `{{feature}}` и нет зашитого id вроде `new-card`.
- `diff -rq docs/settings apps/server/test/fixtures/docs/settings` пустой.
