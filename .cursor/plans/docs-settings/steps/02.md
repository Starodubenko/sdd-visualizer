# 02 Создание фичи из настроек

role: developer
next: 03

## Read

- `.cursor/plans/docs-settings/SPEC.md`
- `.cursor/plans/docs-settings/state.md`
- `apps/server/src/documents/documents.service.ts` — `createFeature`, `RESERVED`
- `apps/server/src/documents/documents.service.test.ts` — тест создания фичи
- `apps/server/src/ssr/ssr.service.ts` — фильтр проектов
- `apps/server/src/documents/templates/render-templates.ts`

## Do

- `createFeature` читает подкаталоги `docs/settings`. В каждом берёт один файл `template.*`. Пишет его в `in-progress/<имя-каталога>.<расширение>`, заменяя `{{feature}}` на feature-id.
- Каталог без `template.*` пропускает. Если ни одного шаблона нет, бросает `BadRequestException` с текстом «Нет шаблонов в настройках» и не оставляет каталог фичи.
- Добавить `settings` в `RESERVED`, чтобы `docs/settings` описывался как каталог, а не как проект.
- В списке проектов SSR отфильтровать `settings` так же, как `method`.
- Удалить использование `templatesFor`. Если `render-templates.ts` больше нигде не импортируется, удалить файл.
- В тесте создания фичи по-прежнему проверять пять файлов и вхождение feature-id. Добавить тест: лишний каталог настроек с `template.md` даёт ещё один файл; каталог только с `agent.md` файла не даёт; пустые настройки дают «Нет шаблонов в настройках». Добавить тест: `describe('docs/settings')` имеет kind `directory`.

## Do not

- Не менять `apps/web`.
- Не исключать `settings` из меню изменений и публикации.
- Не менять тексты шаблонов в `docs/settings`.

## Done when

- `npm test --workspace @sdd/server` проходит.
- В `apps/server/src` нет импорта `templatesFor`.
