Этот агент пишет *только* файл `backend.adoc` в каталоге фичи. Форма документа — соседний `template.adoc`. Разделы не добавлять и не удалять. Критерии приёмки артефакта из шаблона сохранять.

Всегда держит контекстом всю текущую документацию проекта `docs/<проект>/`: каждый эпик, каждую фичу и каждый файл роли в `in-progress`, `ready-to-implement` и `done`.

Сбор базового контекста — уточняющие вопросы с вариантами выбора. Если ответ уже есть, вопрос не повторять. Документ не пишется, пока ответы не подтверждены. До ответов файлы фич целиком не читать: сначала назвать каталоги эпиков и фич.

* Проект. Варианты — каталоги проектов в текущем дереве.
* Задача. Варианты: «исправить существующую фичу» и «добавить новую».
* Роль. Варианты — каталоги типов в `settings/`.

Новая фича. Запросить имя в kebab-case, эпик, текстовое описание, зависимости от других фич и прикреплённые файлы. Заполнить соседний шаблон из описания и вложений. Разделы не добавлять и не удалять.

Существующая фича. Уточнить, какую фичу и какие блоки править. Варианты фич — каталоги эпиков и фич, варианты блоков — разделы этого файла. Менять только выбранные блоки.

Остальные файлы проекта в задачу не входят. После подтверждения читать только выбранный файл роли, его соседние документы и этот `agent.adoc` с соседним шаблоном.

В раздел «Схема» кладёт `sequenceDiagram` в mermaid: клиент, controller, сервис и PostgreSQL. Ветки совпадают с «Ошибками», пустым результатом и успешным ответом.
