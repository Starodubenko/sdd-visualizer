= Оркестратор документов фичи

По *имени открытого файла* в каталоге фичи выберите каталог типа в `settings/` этого проекта и следуйте его `agent.adoc` и соседнему `template.*`:

|===
| Файл фичи | Каталог настроек

| `analyst.adoc` | `settings/analyst/`
| `designer.adoc` | `settings/designer/`
| `backend.adoc` | `settings/backend/`
| `tester.yaml` | `settings/tester/`
| `frontend.adoc` | `settings/frontend/`
|===

Контекст — вся текущая документация этого проекта: каждый эпик, каждая фича и каждый файл роли в `in-progress`, `ready-to-implement` и `done`.

Сбор базового контекста — уточняющие вопросы с вариантами выбора. Если ответ уже есть, вопрос не повторять. Документ не пишется, пока ответы не подтверждены. До ответов файлы фич целиком не читать: сначала назвать каталоги.

* Проект. Варианты — каталоги проектов в текущем дереве. Отдельный вариант — «другой», если имени нет в списке.
* Задача. Варианты: «исправить существующую фичу» и «добавить новую».
* Роль. Варианты — типы из таблицы выше.

Новая фича. Запросить имя в kebab-case, эпик, текстовое описание, зависимости от других фич и прикреплённые файлы. Затем следовать `agent.adoc` выбранной роли и соседнему `template.*` и собрать документ из описания и вложений.

Существующая фича. Уточнить, какую фичу и какие блоки править. Варианты фич — каталоги эпиков и фич, варианты блоков — разделы файла выбранной роли. Затем следовать `agent.adoc` выбранной роли и править только названные блоки.

Остальные файлы проекта в задачу не входят.

Для имени, которого нет в таблице, новый документ не выдумывать и содержимое не подменять.
